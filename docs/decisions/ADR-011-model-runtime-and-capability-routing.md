# ADR-011: Model Runtime and Capability Routing

Status: accepted

## Context

Sprints 4–5 (ADR-009, ADR-010) produced a trustworthy deterministic managed Runtime, but a workflow reaching a `model` node could only fail preflight with `NODE_EXECUTOR_NOT_FOUND`. `ModelPolicySpec` has existed as a canonical, provider-neutral contract since Sprint 2 (ADR-007), with `constraints` left deliberately opaque. Sprint 0A.1 (ADR-000, `packages/substrate-spikes/src/model.ts`) proved the Vercel AI SDK path `AAO abstraction → ai.generateText → Output.object → ai/test model` works offline with the installed `ai@7`. AAO now needs a first production model execution layer that the Runtime can use without the external framework defining AAO semantics.

## Decision

- Model execution is a distinct AAO Core subsystem in a new package, `@aao/model-runtime`. It is not added to `@aao/runtime`: the generic workflow Runtime keeps knowing only `NodeExecutor`, never models, providers, prompts, or the AI SDK.
- `@aao/model-runtime` owns provider-neutral, JSON-safe `ModelMessage` (`system | user | assistant`, string content), `ModelRequest` (`schemaVersion`, caller-owned `invocationId`, `messages`, `output`, optional `requiredCapabilities`, optional `maxOutputTokens`), `ModelResult`, and `ModelFailure`. Output modes are `text` and `structured`; a structured output carries a standard JSON Schema document (top-level object), never a custom schema language.
- Structured output is validated twice where practical: the AI SDK sends the schema to the provider and parses JSON; AAO then validates the parsed object itself with Ajv (strict mode, an established validator — no home-grown JSON Schema implementation). A result the provider claims succeeded but that violates the schema is `MODEL_OUTPUT_SCHEMA_MISMATCH`, never success. All model data crossing the AAO boundary is checked with the canonical `isJsonSafe` from `@aao/runtime` — no second JSON-safety implementation.
- Model capabilities (`model.text_generation`, `model.structured_output`) are properties of inference endpoints. They are not the Integration Fabric's `CapabilitySpec` and do not use its registry. Only capabilities V1 uses exist.
- An explicit, isolated Model Registry holds bindings `{ id, priority, capabilities, adapter }`. Binding ids are AAO ids, not provider model names. No global singleton, no environment discovery; duplicates are rejected.
- Routing is deterministic: required capabilities = policy ∪ request ∪ output-implied, deduplicated; filter bindings declaring all of them; prefer the highest explicit `priority`; tie-break by binding id (code-unit order). Registration order, randomness, latency, cost, history, and LLMs play no part. No adaptive, cost, or quality routing yet.
- Exactly one binding is selected and invoked once. There is no automatic fallback to another compatible binding and no automatic retry (the AI SDK adapter sets `maxRetries: 0`). Silent fallback would change quality, latency, cost, and compliance; reliability policy belongs to later, evaluated work.
- `ModelPolicySpec` remains canonical and is reused, never redefined. An explicit Model Policy Registry provides lookup by id. Because V1 defines no constraint semantics, any non-empty `constraints` fails closed (`UNSUPPORTED_MODEL_POLICY_CONSTRAINTS`) rather than being silently ignored.
- A provider-neutral `ModelAdapter` interface (`invoke(ModelAdapterRequest) → ModelAdapterResult`) uses AAO-owned data only. The first production adapter, `createVercelAiModelAdapter({ model })`, is the only module that imports `ai`, and is exposed from the `@aao/model-runtime/vercel-ai` subpath so the package entry point never loads `ai`. The actual `LanguageModel` is injected: the adapter never reads `process.env`, credentials, or chooses a provider. No provider SDK is a dependency.
- The failure taxonomy is `INVALID_MODEL_REQUEST`, `MODEL_POLICY_NOT_FOUND`, `UNSUPPORTED_MODEL_POLICY_CONSTRAINTS`, `MODEL_ROUTE_NOT_FOUND`, `MODEL_INVOCATION_FAILED`, `INVALID_MODEL_RESULT`, `MODEL_OUTPUT_SCHEMA_MISMATCH`. Expected failures are values; provider errors are redacted to a safe enumerated `reason` (never `Error.message`, stack, thrown object, URL, or headers).
- The `model` node is bridged by `createModelNodeExecutor({ models, policies })`, a `NodeExecutor` that callers register explicitly; the generic Runtime registers nothing model-related. Its config is `{ modelPolicyRef, requestStateKey, resultStateKey }` (top-level state keys only). It reads a prepared `ModelRequest` from `RunState.values[requestStateKey]` and proposes `{ [resultStateKey]: ModelResult }` as a state patch; the Runtime applies it and advances revision. On failure it throws, so the Runtime marks the node `FAILED`, the Run `FAILED`, applies no patch, and exposes only its redacted `NODE_EXECUTION_FAILED`. The direct `executeModelRequest` API keeps the specific model taxonomy.
- `NodeExecutor` gains one optional, deterministic, side-effect-free hook, `validateConfig({ node }) → { ok } | { ok: false, issues }`, which Runtime preflight calls for every node after executor-registration checks and before any node executes (`RUNTIME_PREFLIGHT_FAILED`). The model node uses it to reject malformed config, an unregistered `modelPolicyRef`, or a policy with unsupported constraints. This is not a plugin lifecycle.
- Out of scope: prompt templating/DSL, tools or tool calling (a tool-call response fails closed), agents, reflection/evaluator loops, streaming, multimodal input, embeddings, model memory or conversation persistence, caching, persistence, credentials, and any live provider in tests or CI.

## Consequences

- New package `packages/model-runtime`; `@aao/runtime` changes only by the optional `validateConfig` hook and its preflight step. A Runtime without a registered model executor still returns `NODE_EXECUTOR_NOT_FOUND` for a model node.
- `ajv` becomes a direct dependency of `@aao/model-runtime` (it was already in the lockfile transitively). Consequence of strict mode: a structured schema using an unknown keyword or a `format` is rejected as `INVALID_MODEL_REQUEST` (fail closed) rather than partially enforced.
- Routing determinism is proven; model-generation determinism is not claimed for real providers — only for the `ai/test` models used in tests.
- The Sprint 0A model spike (`packages/substrate-spikes/src/model.ts`) is kept as research evidence; its semantics are promoted into the production adapter, and production code does not depend on it.
- Sprint 7 (Bounded Agent Runtime) builds on managed Runtime + Model Runtime rather than bypassing them.
