# ADR-009: Node Registry and Runtime V1

Status: accepted

## Context

Sprint 3 produced `@aao/workflow-dsl`'s `CompiledWorkflowPlan`: a framework-neutral, JSON-safe, deterministic artifact — but nothing in the repository executed it. No Node Registry, execution engine, or LangGraph integration existed. Before AAO can execute even the simplest governed workflow, it needs a trusted boundary that turns a compiled plan into deterministic execution: resolving each node to a trusted implementation, applying validated state changes, and producing a structured result or a structured failure — without yet touching models, tools, agents, approvals, or persistence.

## Decision

- `@aao/runtime` (`packages/runtime`) is the first production execution engine. It consumes `@aao/contracts` and `@aao/workflow-dsl` as canonical sources of truth and never redefines `NodeKind`, `Workflow`, `RunState`, or `CompiledWorkflowPlan`.
- The Runtime never parses workflow source. Its input is an already-compiled `CompiledWorkflowPlan`; compiler responsibilities (graph integrity, reachability, cycles, structural routing validity, terminal semantics) are not re-litigated at the Runtime boundary.
- A Node Registry is explicit and constructible (`createNodeRegistry()`), never a global singleton or module-level `Map`. `register` rejects a duplicate `kind`. Workflow authors cannot register executors — only trusted calling code can; node `config` remains inert JSON data until a registered executor interprets it.
- A `NodeExecutor` is a framework-neutral, runtime-specific contract (`kind`, `execute(context)`). `NodeExecutionContext` injects only `runId`, `node`, a defensively cloned `state`, and `step` — no Fastify, Worker, `process.env`, filesystem, database, MCP, model SDK, or company-specific service.
- An executor never mutates authoritative state directly. It returns a `NodeExecutionResult` (`statePatch?`, `output?`); the Runtime validates and applies it. Executor output is validated against a strict JSON-safety check (rejecting function values, `Date`/`Map`/`Set`/class instances, and unknown keys) before it is trusted, distinct from a merely structural check that could be fooled by an object with no own enumerable properties.
- Runtime V1 state semantics are the smallest deterministic rule that satisfies the canonical `RunState` contract: a `statePatch` is a shallow top-level merge into `RunState.values` (nested objects replaced wholesale, not deep-merged); `revision` increments by exactly one only when a patch is actually applied. No reducer registry, deep merge, delete operator, CRDT, conflict resolution, or persistence is introduced — deferred to Sprint 5.
- A deterministic Runtime preflight runs before any node executes: compiled-plan integrity (defensive, cheap), conditional-routing rejection (`CONDITIONAL_ROUTING_UNSUPPORTED` — Runtime V1 does not evaluate `Edge.condition`), unconditional-routing arity, and registered-executor presence (`NODE_EXECUTOR_NOT_FOUND`). A workflow that is compiler-valid but exercises an unsupported Runtime V1 capability fails preflight wholesale rather than partially executing.
- Runtime V1 supports only unconditional sequential execution, following exactly the plan's indexed `outgoingEdgesByNode`. `final_output` is a minimal generic executor returning `RunState.values`; no field-selection DSL, templating, or rendering exists yet.
- A small, JSON-safe, deterministic Runtime-specific failure taxonomy (`INVALID_RUNTIME_INPUT`, `RUNTIME_PREFLIGHT_FAILED`, `NODE_EXECUTOR_NOT_FOUND`, `CONDITIONAL_ROUTING_UNSUPPORTED`, `NODE_EXECUTION_FAILED`, `INVALID_NODE_RESULT`, `INVALID_STATE_PATCH`, `MAX_STEPS_EXCEEDED`) is returned as a value (`{ ok: false, failure }`), never thrown for expected conditions. An executor throwing is normalized to `NODE_EXECUTION_FAILED` with a safe message; no raw stack trace or arbitrary thrown value is exposed. No retries, replanning, or recovery loops exist.
- Execution is bounded by a defensive `maxSteps` ceiling (default: node count + a small fixed allowance) as protection against a corrupted plan or a future implementation bug — Workflow Compiler V1 already rejects cycles, so this is not a feature workflows are expected to rely on.
- No persistence, external side effect, model/tool/agent/approval/evaluator executor, or company-specific logic is introduced. `createRuntimeV1Registry()` wires up exactly one executor (`final_output`); it never auto-registers a fake executor for an unimplemented node kind.
- LangGraph remains deferred. Runtime V1 is a small deterministic executor over an already-compiled plan, not a graph framework; a future runtime *adapter* may translate onto LangGraph (or any other substrate) behind a boundary if agentic graph behavior, interrupts, or durability later justify it — the dependency direction never flows the other way.
- The Node Registry remains inside `@aao/runtime` rather than a separate package until independent reuse is evidenced — the smallest reliable architecture first, matching the pattern `@aao/workflow-dsl` established for graph semantic validation living alongside its compiler rather than as its own package.
- `CompiledWorkflowPlanSchema` is added to `@aao/workflow-dsl` (not duplicated inside `@aao/runtime`) so the Runtime can defensively validate a plan it did not itself produce, since the compiled plan is owned by the compiler package. `@aao/workflow-dsl` gains `zod` as a direct production dependency for this reason.

## Consequences

- `packages/runtime` builds and typechecks independently, with its own test suite covering the Node Registry, executor-result validation, state-patch/revision semantics, preflight (including corrupted-plan defense), successful execution, safety (missing executors, unsupported node kinds, conditional rejection, executor throws, malformed results, step-ceiling), integrity (no mutation of the caller's plan/state, deterministic ordering, no double execution, no downstream execution after failure), serialization, determinism, and a dependency/vendor-import boundary check — matching the verification pattern `@aao/contracts` and `@aao/workflow-dsl` established under ADR-007/ADR-008.
- A real cross-package integration test exercises YAML source → `@aao/workflow-dsl`'s actual parse/compile pipeline → `@aao/runtime`'s actual engine → custom deterministic executors → `final_output`, with no fake compiled plan — the first real AAO end-to-end execution path, entirely local and deterministic.
- `apps/control-plane` and `apps/worker` remain unconnected to the Runtime; there is still no persistence, run scheduling, durable state, job ownership, or approval-wait infrastructure to justify wiring it into the Worker operationally.
- Sprint 5 (State, Run Lifecycle & Runtime State Management) can now assume a deterministic, tested execution engine exists for unconditional workflows and can focus on deepening state/reducer semantics and run lifecycle without re-litigating Node Registry or preflight design.
- `@aao/runtime` is the third package (after `@aao/workflow-dsl` depending on `@aao/contracts`) to import a sibling workspace package by name at runtime, which resolves through that package's compiled `dist/` (`package.json` `"main"`), not its TypeScript source. This sprint's own validation surfaced that the root `check` script and CI ran `test` before `build`, so a truly clean checkout could never pass `pnpm test` on its own — a latent gap present since Sprint 3, not introduced here. Both were reordered to `typecheck → lint → build → test` (see `package.json` and `.github/workflows/ci.yml`); no check was removed, only reordered.
